# dsh-screen-recorder 设计规格

这份文档写给要改这个插件的人：它为什么被拆成这些模块、每个决定放弃了什么、以及哪些地方看起来可以简化但**不能**简化。

---

## 1. 分工

```
DSH（模型）
   │  决定：录多久、录哪儿、要不要声音、结构读起来对不对
   ▼
dsh-screen-recorder（本插件）
   │  执行：调 ffmpeg 采集、解码、抽帧、调用识别组件
   │  测量：解码数帧、比对时长、算占比、报置信度
   ▼
结构文档 / 关键帧 / 联系表 / 交付视频 / 章节
```

插件不做任何"这段很重要""这个分段很合理"的判断。它可以报"这一段的暗色区域占 42%"，但不报"这一屏是终端所以重要"——`kind` 是**规则给出的外观标签**，规则与阈值都在 `src/core/analysis.mjs` 的 `KIND_RULES` 表里，可以被反驳。

**邻居边界**（越界就是设计错误）：

| 事情 | 归谁 |
| --- | --- |
| 转码、裁剪、拼接、抽帧做封面、烧字幕 | `dsh-ffmpeg` |
| 只读文字与坐标、按文字点击 | `dsh-ocr`、`dsh-computer-use` |
| 音频测量 / 降噪 / 事件检测；ONNX 运行时 | `dsh-video-audio` |
| 成片、旁白、字幕、素材编排 | `video-factory` |
| **录屏** 与 **把录屏读成结构** | 本插件 |

## 2. 模块地图

```
index.mjs                  Host 插件入口：校验配置 → 注册工具（不 import 任何 harness 包）
cordis.patch.yml           一行 bundle patch + 全部可配置项与默认值
src/tools/
  registry.mjs             唯一的文档源：工具/action/参数/返回/坑 + playbook + rules
  shared.mjs               从 registry 生成 schema；JSON 无损化；参数读取与拒绝
  index.mjs                注册五个工具，逐个 try/catch，失败不影响其余
  env.mjs setup.mjs record.mjs analyze.mjs guide.mjs
src/core/
  home.mjs env.mjs         插件在哪、共享目录在哪、这次用哪份 ffmpeg（每一次都报来源）
  ffmpeg.mjs               唯一的进程入口：并发上限、超时杀进程、stdout 流式
  caps.mjs                 这份构建能不能 gdigrab/dshow/编码/滤镜（动手前先问）
  devices.mjs              DirectShow 设备名（故意"列出"而不是"总结"）
  container.mjs            容器与编码器的显式表（不靠扩展名猜）
  record.mjs               采集计划 + 采集后测量（capture / measureCapture）
  probe.mjs image.mjs      文件是什么；一帧像素怎么读、怎么折回源坐标
  timeline.mjs             一次解码切时间轴（流式帧差 + 纯切分算术）
  segmentation.mjs         关键帧的区域外观分割（纯阈值）
  ocr.mjs                  同级 dsh-ocr 优先 → Windows OCR 兜底
  vision.mjs               ONNX 运行时发现 + YOLO 推理 + 两种张量布局的解码 + NMS
  vision-install.mjs       权重下载/校验/删除；运行时借用而非重下
  asr.mjs                  16k 单声道转换 + 停顿切分 + 逐段识别 + 时间对齐
  analysis.mjs             默认值表 + 命名规则 + 关键词 + 时间轴归属（纯函数）
  structure.mjs            融合与写盘（analyzeRecording）
  download.mjs             fetch 失败后退回 curl + 系统代理
  net.mjs                  带 sha256 校验的下载原语（与 dsh-ffmpeg 同源）
  install.mjs              共享目录里的 ffmpeg 安装（与 dsh-ffmpeg 同源）
  index.mjs                对外只暴露 core 的公共面
src/bin/winrt-ocr.ps1      Windows OCR 桥（UTF-8 with BOM；JSON 契约写在 ocr.mjs 头部）
```

## 3. 数据流：一次 `analyze`

```
probeMedia ──→ 宽高/时长/有无音轨/问题清单
     │
detectScenes ──→ 一次解码：[fps, scale=偶数尺寸, rawvideo gray] 流式读
     │              逐帧平均亮度差 → 越线切 / 超长切 / 太短不回切 / 太短向前吃
     ▼
segments[]  ──抽帧(≤ maxKeyframes, 长边 ≤1920)──→ 关键帧 jpg
     │                                              │
     │                    ┌─────────────────────────┼───────────────────────┐
     │                    ▼                         ▼                       ▼
     │            segmentImage(网格外观)      ocrImage(文字+框)      detectFrame(YOLO)
     │                    │                         │                       │
     ▼                    └────────────┬────────────┴───────────┬───────────┘
  classifySegment ←──── 证据(占比/行数/框/帧差)
     │
     │   transcribeIntervals ──→ 语音段[{start,end,text}] ──textWithin()──→ 每段的 speech
     ▼
structure.json + keyframes/ + contact-sheet.jpg + delivery.mp4 + chapters.txt
```

四个阶段的失败都被吸收成 `warnings` 或某个 `available:false` 的节，**不会**让整份文档消失——半份结构仍然可用，而且读者知道少了哪一半。

## 4. 关键决定（以及被放弃的东西）

### 4.1 录制必须给秒数

没有"录到我说停"。理由：一个没有结束条件的采集是一个可能永远不返回的进程，而工具调用必须能结束。代价是无法录一个"事件驱动"的片段；补偿是 `seconds` 上限 3600，且长素材可以分段录。

### 4.2 录完一定解码数帧

`ffmpeg` 退出码 0 只说明进程结束了。`measureCapture` 用 `ffprobe -count_frames` 真解一遍，比对时长与帧数，再检查音频流是否存在。**`ok` 是这三个结论的合取**，而不是"进程没报错"。

### 4.3 时间轴自己算，不解析 `showinfo`

帧差在进程内算：`-f rawvideo -pix_fmt gray` 流式读，逐帧求平均绝对亮度差。选它而不是 `select='gt(scene,...)'` 的原因：需要每段的**运动量**而不只是切点，且流式读让一小时的素材不需要缓冲全部像素。

`'motion'` 理由是确定性的：越线之前若已连续 ≥3 帧达到 `sceneThreshold/3`，这个边界记成 `motion` 而不是 `scene_change`。**代价**：重动画里的硬切会被记成 `motion`（写进了 `timeline.mjs` 头部的已知限制）。

### 4.4 关键帧尺寸 1920，而分析帧 320

两件事要的像素不一样：切分只要亮度，越小越快；OCR 要笔画，越小越糊。所以时间轴用 320 长边解码，关键帧按源分辨率抽（长边上限 1920），OCR/分割/检测都吃同一张关键帧——**一次解码，三个消费者**。

联系表因此要把关键帧缩到 384 宽再拼，否则 5×4 的拼图是 9600 px 宽，没有工具打得开。

### 4.5 YOLO 的两种张量布局都要认

导出来源不同布局不同：v8 是 `[1, 4+nc, N]`（通道在前），v5 是 `[1, N, 5+nc]`（行在前，多一个 objectness）。判据不是"哪个维度小"——那在行数很少的张量上会判错——而是**哪个维度落在合理的通道范围内（5…1024）**。dtype 也两种都认（`float16` 的导出体积只有一半）。**代价**：解码多了一层分支，收益是操作者手上那份权重能不能用不再取决于导出工具。

### 4.6 语音按"停顿之间"切，而不是整段丢给识别器

宿主一次只收 ≤4 MB（约 131 秒），且只返回整段文本、没有逐词时间戳。所以：`silencedetect` 找停顿 → 停顿之间就是语音段 → 逐段识别 → 每段带自己的 `start/end`。这样文字能贴到时间轴上（`textWithin()` 按重叠归属），代价是**对齐粒度是一个停顿，不是一个词**。

停顿太多时按"间隔最近的一对"合并，直到请求数 ≤ `maxIntervals`；合并过的结果在 `notes` 里说明——粗边界是被报告的，不是被隐藏的。

### 4.7 下载走两条路

`fetch` 是快路。但 Windows 上 `fetch` **故意不读**系统代理设置，而浏览器和 PowerShell 会读——于是会出现"`Invoke-WebRequest` 能下载、插件不能"的机器（本项目的一台就是）。所以 `download.mjs` 在 `fetch` 失败后：从注册表读系统代理 → 交给 `curl.exe` 重试一次 → 报告走的是哪条路。两条都不通才失败，且失败信息里给出 `archive` 这条退路。

### 4.8 共享运行时是"借"，不是"再下一份"

13 MB 的 ONNX WASM 运行时由 `dsh-video-audio` 拥有。本插件**不会**下载第二份：它按 顺序找 `DSH_AUDIO_VENDOR` → 共享目录 → 同级检出的 `vendor/audio`，找不到时从同级复制一份进来，再找不到就在 `reason` 里点名去哪个插件装。

### 4.9 文档即产品，产物是附加

`structure.json` 是这次分析的成果；交付视频、联系表、章节文件是顺手产物。任何一个写失败都只进 `warnings`，不影响结构本身——因为结构已经算完并且在内存里了。

## 5. 结构文档的稳定性

- `structureVersion` 是文档形状的版本号；形状变了就加一。
- 字段只增不改语义：新增一律是可选的、缺省为 `null` 的字段。
- 每个可能的"没有"都是显式的 `null` + 原因，不用 `0`、不用空字符串、不删键。`shared.mjs` 的 `toLosslessJson` 在结果离开插件前统一把关（`undefined`/`NaN`/`-0` 都是 JSON 边界的陷阱）。

## 6. 错误模型

| 类型 | 什么时候 | 谁来接 |
| --- | --- | --- |
| `FfmpegNotFound` | 一条路径都没找到 ffmpeg | 工具直接失败，信息里给出安装动作 |
| `MediaError` | ffmpeg/ffprobe 非零退出、超时、输出超限 | 工具失败；采集类会删掉半成品 |
| `ContainerError` | 输出扩展名装不下要求的内容 | 计划阶段就失败，机器还没开始录 |
| `RecordError` | 秒数/帧率/参数不合法 | 同上 |
| `VisionError` | 模型或运行时不在、张量形状不认识 | `detect` 失败；`analyze` 降级为 `objects.available=false` |
| `OcrError` | 两个识别引擎都不可用 | `ocrImage` 失败；`analyze` 降级为 `text.available=false` |
| `TranscribeError` | 宿主没有语音服务、音频为空 | `transcribe` 失败；`analyze` 降级为 `speech.available=false` |
| `InstallError` | 下载失败、摘要不符、压缩包不合法 | 安装类失败；已下载的坏文件会被删掉 |

规矩：**能被降级的失败必须降级，不能降级的失败必须给动作。** 前者对应 `analyze` 的四个可选组件，后者对应"装 ffmpeg"这类没得商量的事。

## 7. 测试策略

`node --test "tests/*.test.mjs"` 不需要 ffmpeg、不联网、不录屏，覆盖：

- **切分算术**：越线/超长/太短/封顶/运动判定的纯函数（`mergeSegments`、`SegmentBuilder`）。
- **区域分割**：合成像素上的阈值行为、瓦片与块合并、占比按最大余数法凑成 1、退化输入。
- **YOLO 解码**：两种布局、两种 dtype、letterbox 折回、越界裁剪、NMS 只压同类。
- **语音**：silencedetect 解析、语音段推导、超长切开、请求数合并、按停顿选切点。
- **插件自身**：五个工具都注册、schema 与 registry 一一对应、每条描述存在、非法 action/参数被拒绝、`toLosslessJson` 的边界。
- **配置**：非法配置在激活时就失败，且信息点名字段。

真跑的部分在 `scripts/verify-e2e.mjs`：真的录 6 秒桌面、真的抽帧、真的 OCR、真的跑 YOLO、真的切音频并（用替身识别器）验证时间对齐，最后检查产物落盘。
